结论：

- 核心功能各家都有：分区、自动归类、文件夹映射、折叠、双击隐藏。Fences 额外有标签页、Peek、布局快照。
- 国产软件的通病是附带壁纸、资讯、待办，越做越重。本项目只做整理，不加这些东西。
- Fences 6.46 在 24H2 上有用户反馈“快捷方式偶尔掉出磁贴”，Stardock 复现不了。这是挪 Explorer 图标这种做法的固有风险：系统更新、切换虚拟桌面或重启 Explorer 都可能打乱位置。

## 2. 功能清单

### 第一版

1. 磁贴：圆角半透明面板（Win11 亚克力 / Mica），拖动、改尺寸、吸附屏幕边缘和其他磁贴，内容超出时可滚动。
2. 自动归类：桌面上新出现的、不属于任何磁贴的散文件按规则归入对应磁贴（规则见第 3 节）。快捷方式不动。
3. 原生操作：双击打开、右键弹出系统菜单（`IContextMenu`，和资源管理器里的右键菜单一样）、F2 重命名、拖进拖出（拖到其他程序、拖进回收站）、多选、Ctrl+C / X / V、Delete。
4. 手动归类会记住：把一个文件从 A 磁贴拖到 B 磁贴时，提示“以后 .xxx 都放这里？”，确认后改写规则。
5. 折叠：双击标题栏收起成一条，悬停或点击展开。
6. 双击桌面空白处隐藏 / 显示全部磁贴。
7. 托盘图标：暂停自动归类、一键全部还原到桌面（卸载前用）、开机自启。
8. 多显示器、DPI 缩放、分辨率变化时布局按比例保持。

### 后续再做

- 磁贴合并成标签页、Peek 快捷键、文件夹映射磁贴、搜索、按名称 / 日期的规则。
- 不做：壁纸、资讯、待办、天气、图标着色。

## 3. 自动归类规则（默认）

| 磁贴 | 归入条件 |
|---|---|
| 文件夹 | 目录 |
| 文档 | doc docx pdf txt md rtf odt xls xlsx csv ppt pptx wps et dps |
| 图片 | png jpg jpeg gif webp bmp svg heic ico psd |
| 视频 | mp4 mkv mov avi wmv flv webm |
| 音频 | mp3 wav flac aac m4a ogg |
| 压缩包 | zip rar 7z tar gz |
| 程序 | exe msi |
| 其他 | 上面都不匹配的 |

不归类（留在桌面原处）：

- 快捷方式：`.lnk` `.url` `.appref-ms` `.website`。
- 隐藏文件和系统文件（如 `desktop.ini`）。
- 正在写入的文件：下载临时文件（`.crdownload` `.part` `.download` `.tmp`）、Office 锁文件（`~$` 开头）。普通文件要等 3 秒内没有变化、并且能独占打开，才去归类。
- 公共桌面（`C:\Users\Public\Desktop`）里的文件：基本都是安装程序放的快捷方式，移动要管理员权限。

“桌面上新建文本文档 → 正在桌面上重命名”这种情况会被上面的 3 秒等待覆盖：用户重命名期间文件一直在变，不会被拿走。

## 4. 待决策

### 4.1 文件“归入磁贴”后放在哪（需要你定）

| | A. Fences 式：文件不动，挪图标 | B. 移进磁贴目录（推荐） | C. 文件不动，加隐藏属性，自己绘制 |
|---|---|---|---|
| 做法 | 文件留在桌面根目录，跨进程改 Explorer 桌面图标的坐标，挪进磁贴所在的区域 | 每个磁贴对应桌面下一个隐藏子文件夹（如 `桌面\.Nookery\文档\`），归类就是把文件移进去，磁贴自己绘制内容 | 文件留在原处，打上隐藏属性让桌面不显示，磁贴自己绘制 |
| 文件路径 | 不变 | 会变（最近打开列表里的旧路径失效） | 不变 |
| 界面能做多漂亮 | 受限：图标和文字是 Explorer 画的，磁贴内滚动、折叠动画、模糊都只能靠变通手段实现 | 完全自控 | 完全自控 |
| 稳定性 | 差：系统更新、切换虚拟桌面、重启 Explorer、开着“自动排列”都会打乱位置 | 好：只用公开的文件和 Shell API | 中：用户打开“显示隐藏文件”后桌面会出现半透明重影；程序被强杀后文件一直处于隐藏状态 |
| 开发量 | 大，跨进程 hack 最难调 | 中：拖放、右键菜单、重命名要自己接，都有标准 API | 中，和 B 相近 |
| 性能 | 最低：图标由 Explorer 绘制 | 低：只在内容变化时重绘 | 低 |

推荐 B：界面美观、长期稳定，“归入”的语义也最直接。文件仍在桌面目录下，OneDrive 桌面同步照常生效。托盘菜单的“全部还原到桌面”可以随时撤销。

### 4.2 技术栈（推荐 Rust + Win32 + Direct2D）

本机实测（2026-10-17，同一台机器，一个 320×200 的无边框窗口显示一行中文，启动后静置 4 秒再采样；在 Sandboxie 沙箱里测得，绝对值可能偏高，两者之间的比例可信）：

| | 私有内存 | 工作集 | 线程数 | 静置 5 秒的 CPU 时间 | 程序大小 |
|---|---|---|---|---|---|
| Rust + Win32（windows-sys） | 3.9 MB | 13.8 MB | 1 | 0 ms | 105 KB |
| C# WPF（.NET 10，ReadyToRun） | 99 MB | 142.7 MB | 25 | 297 ms | 159 KB + .NET 运行时 |

- WinUI 3、Tauri、Electron 未实测：WinUI 3 同样要加载托管运行时和 XAML 框架；Tauri / Electron 背后有 WebView 或 Chromium 的多个进程。一般认为这三者的内存都在 WPF 的量级或更高。
- Rust 方案：Win32 窗口 + DWM 亚克力背景 + Direct2D / DirectWrite 绘制 + `IShellItemImageFactory` 取系统图标和缩略图 + `ReadDirectoryChangesW` 监听桌面（事件驱动，不轮询）。单进程，接入 D2D 和图标缓存后预计私有内存在 30 MB 以内，原型出来后再实测确认。
- 代价：没有现成的 UI 框架，控件（滚动条、重命名输入框、菜单动画）要自己画。磁贴界面元素不多，工作量可控。

## 5. 性能目标

| 指标 | 目标 |
|---|---|
| 常驻私有内存 | < 30 MB（磁贴里共 200 个文件时） |
| 空闲 CPU | 0（没有定时器、不轮询，只在文件变化或用户操作时工作） |
| 冷启动到磁贴显示 | < 300 ms |
| 新文件归类延迟 | 文件稳定后 1 秒内 |

做法：图标按需加载并缓存，滚动出视野的位图释放；只重绘变化的区域；动画只在播放期间驱动，播完立即停帧。

## 6. 第一版实测（2026-10-17，本机，Sandboxie 沙箱内，用 `scripts/` 下的脚本跑假桌面）

| 指标 | 结果 | 目标 |
|---|---|---|
| 私有内存（14 个测试文件，6 块磁贴） | 12.2 MB | < 30 MB |
| 私有内存（214 个文件，7 块磁贴） | 14.0 MB | < 30 MB |
| 空闲 CPU（静置 5 秒） | 0 ms | 0 |
| 程序大小 | 318 KB，单个 exe，无运行时依赖 | — |
| 双击桌面用的全局鼠标钩子 | 未测（沙箱拦了 SendInput）；估计鼠标移动时每个事件 2~5 µs，鼠标不动时为 0，可在托盘关掉 | — |
| 冷启动到磁贴显示 | 未测 | < 300 ms |

做过的取舍（数据来自 `examples/membench.rs`）：

| 方案 | 私有内存 | 结论 |
|---|---|---|
| 每块磁贴一个 `ID2D1HwndRenderTarget` | 61.6 MB，而且透明背景画不出来 | 弃用 |
| 共用一个硬件 D3D11 设备 + DirectComposition | 62.9 MB，其中硬件设备单项 +47.6 MB（显卡驱动） | 弃用 |
| 共用一个 WARP 设备 + DirectComposition | 11.7 MB；整块磁贴重绘 0.31~0.34 ms（硬件是 0.24~0.28 ms） | 采用 |

背景用 `SetWindowCompositionAttribute` 的亚克力模糊。系统亚克力（`DWMSBT_TRANSIENTWINDOW`）在窗口没激活时会退成纯色，而磁贴几乎总是处于未激活状态。

第一版之后补上的：拖入高亮和拖拽缩略图（OLE 拖放目标）、双击桌面空白处隐藏 / 显示、资源管理器重启后重建磁贴、首次运行确认、从磁贴拖回桌面的文件留在桌面、方向键导航、改尺寸吸附和最小尺寸。

设计走查（2026-10-17，按 design-review 两轮，第 2 轮零缺陷）定下的 token：

| 项 | 取值 | 依据 |
|---|---|---|
| 字号 | 12（文件名、数量、提示）/ 14 半粗（标题），1.2 比例 | 只有两档 |
| 字体 | Segoe UI Variable Text，中文自动回退微软雅黑 | 和 Win11 资源管理器一致 |
| 间距 | 4 / 8 网格：标题栏 36，内边距 8，格子 84×88，图标 40，图标到文件名 8 | — |
| 深色 | 底色 #202020 不透明度 78%，文字 #F3F3F3，次要文字 74% | `scripts/contrast.ps1`：亚克力背后是纯白时正文 7.15:1、次要 4.78:1 |
| 浅色 | 底色 #F3F3F3 不透明度 88%，文字 #1A1A1A，次要文字 74% | 背后是纯黑时正文 11.96:1、次要 6.01:1 |
| 状态 | 悬停叠 8%，按下叠 16%，选中用系统强调色填充 32% 加 1px 边框，键盘焦点 2px 文字色描边 | 选中不只靠颜色：有边框 |
| 动效 | 不加 | 动画期间要逐帧重绘，空闲 CPU 就不是 0；折叠和悬停都是瞬时切换，和资源管理器桌面一致 |

已知没法验证或没做的：悬停高亮和拖入高亮（测试时没有真实鼠标和真实 OLE 拖拽）、150% / 200% 缩放、Win+D 后磁贴是否留住；浅色主题下，个别程序自带的白色图标（如本机关联 docx 的 ChatGPT 图标）看不清，这是原版图标本身，没加底板。还没做：Peek、标签页、文件夹映射、搜索。

## 7. 第二版（2026-10-17，按试用反馈）

| 反馈 | 做法 |
|---|---|
| 磁贴停在任意位置，可锁定 | 吸附距离 12px 改成 8px，按住 Alt 不吸附；标题栏右上角的数字换成锁按钮（Segoe Fluent Icons 的锁图标），锁定后不能拖动、不能改尺寸，存进配置 |
| 单击名字改名，名字居中，不显示程序图标 | 标题栏改成客户区：单击名字进入改名；按住拖动交给系统移动循环（`WM_NCLBUTTONDOWN` + `HTCAPTION`），松手时位置没变就当单击。改名框无边框、配色跟主题，点别处失去焦点即保存 |
| 透明度可调，最高全透明只留不明显的边框 | 托盘里五档：100 / 75 / 50 亚克力磨砂，25 半透明不模糊，0 全透明。0% 时去掉 `WS_THICKFRAME` 和 DWM 非客户区渲染，消掉阴影，自己画外白内黑两圈淡边框；≤50% 文字改成白字加四向暗边 |
| 标题行有折叠 / 展开快捷按钮 | 锁按钮左边加折叠按钮；鼠标在磁贴上时显示，已折叠时一直显示展开箭头 |
| 磁贴右键菜单只留删除和在资源管理器打开 | 照做；粘贴改用 Ctrl+V |
| 新建磁贴绑到桌面右键菜单 | 写 `HKCU\Software\Classes\DesktopBackground\Shell\NookeryNew`，命令带 `--new-tile`；程序已在运行时，新进程把鼠标位置转给它后立即退出 |
| 双击隐藏时弹提示 | 双击处上方弹深色胶囊提示，停 1.4 秒后 8 帧淡出，只在淡出时重绘 |

实测：私有内存 11.8 MB，空闲 CPU 0。走查取证在花哨的假壁纸（`scripts/backdrop.ps1`，近白和高饱和色块）上截了深色 100 / 75 / 50 / 25 / 0% 和浅色 100%，存档在 `C:\WorkFile\Output\2026-10-17-Nookery设计走查\`。

限制和没验证的：

- Windows 11 的新式右键菜单只认 MSIX 打包应用的扩展，“新建磁贴”只出现在“显示更多选项”里；要进第一层得打包成 MSIX 并写 COM 扩展。
- 家里沙箱写注册表不落到真实系统，桌面右键菜单只能在沙箱外验证。
- 没锁定时“单击名字改名、按住拖动”走系统移动循环，要真实鼠标才能测；锁定后的改名测过。
- ≤50% 时白字加暗边在纯白壁纸上仍偏弱，和资源管理器桌面图标文字同一个问题，没有办法保证 4.5:1。
